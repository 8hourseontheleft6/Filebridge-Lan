# Filebridge-Lan 1.6.0 Preview 1

发布日期：待 Draft 真机验收后确定

1.6.0 Preview 1 新增经过主机批准连接内的纯文本剪贴板同步。文件传输、Safari 分块上传、断点续传、局域网发现和 Public 门禁保持 1.5.6 的行为。

## 文字同步

- 默认开启，可随时关闭；只有主机本机 loopback 可以切换，已批准并持有有效 token 的连接才可读写。
- 电脑剪贴板文本变化会同步到手机网页；手机发送的文本会写入电脑系统剪贴板。
- 手机端显示最新文本、更新时间、来源和“复制”按钮，并提供“从剪贴板读取”、手动输入、发送和清空。
- 文本上限 256 KiB，只支持 `text/plain`；超限明确拒绝。
- 内容只保存在 Hub 内存中，不写入磁盘、发现广播、URL、诊断或日志；关闭同步、断线或 Public 暂停时客户端清空当前文本缓存。
- 发送端带来源和内容 SHA-256；服务端对相同哈希去重，避免电脑与手机之间形成同步回声。
- Node Hub 与 Rust Hub 使用相同的 `/api/clipboard`、`/api/clipboard/enabled` 协议、错误码和大小限制。

## 浏览器限制

移动浏览器通常不允许网页在后台静默写入系统剪贴板：

- 收到文本后保留在页面中，由用户点击“复制”；
- 只有浏览器允许且页面在前台时才尝试 `navigator.clipboard.writeText`；
- 复制失败时文本仍保留，并提示长按/选择手动复制；
- 手机发送可使用“从剪贴板读取”；权限被拒绝时仍可手动输入或粘贴；
- 不承诺后台自动复制，也不承诺所有浏览器都允许读取剪贴板。

## 桌面端

- 桌面端新增“文字同步”卡片，不占用文件列表主流程。
- 系统剪贴板只在同步开启、窗口聚焦、连接在线且未 Public 暂停时读取。
- 系统剪贴板写入失败会显示真实错误。
- 轮询间隔 2.5 秒，并用内容哈希与来源去重。
- 新增 Windows 系统剪贴板读写命令，不引入云服务或公网依赖。

## 安全边界

- 发现广播仍只包含设备名、实例 ID、端口和现有版本字段。
- 文本内容不会进入发现广播、URL query、上传诊断或普通日志。
- 接口要求已批准 token；开启接口只允许 loopback。
- 全局与单 IP 写入限流，防止刷写。
- Public/未知网络不启动 Hub，文字同步接口不可用。
