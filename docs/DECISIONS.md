# 1.6.0 正式版前的设计决策记录

记录本轮（2026-11-14）为 1.6.0 正式版做的产品与工程决策，方便后续追溯。日期均为本地时间。

## 1. 跨网络中继的可见性

**背景**：preview.2/3 的顶部模式切换把实验性的「跨网络中继」与「局域网直传」放在同等视觉权重，手机首屏也会出现实验入口。

**决策**（用户给定两个选项，这里选后者并加约束）：

- 取消顶部模式切换条，改为左侧栏「传输方式」分组；
- 桌面应用侧栏保留「跨网络中继」，但作为**次要入口**：次要文字色、较轻字重、右侧「实验」徽标，不再与局域网直传同级；
- **浏览器客户端（手机扫码打开的页面）不显示该入口**；
- **≤1000px 窄屏不显示该入口**（窄屏导航空间有限，且中继本就是桌面自建 Relay 的场景）；
- 进入中继页后顶部给出实验性提示条（需自建 HTTPS Relay、未完成真实 WAN 验证）并提供「返回局域网直传」。

**理由**：中继功能本身仍有价值且已发布，直接删除会让既有用户失去入口；但它未完成真实 WAN 验证，不应与主链路竞争注意力，也不应出现在手机首屏。

## 2. 文字同步卡片的操作层级

**背景**：原面板有 5 个同级动作（复制、从剪贴板读取、清空、关闭同步、发送），默认开启的说明不显眼。

**决策**：

- 开关（关闭同步）移到右上角状态徽标旁，与状态同类；
- 复制升为主操作（主色按钮），清空保留为次要动作；
- 「从剪贴板读取」并入「发送文本」区域，作为该输入框的辅助动作；
- 已开启时固定显示一行提示：文字同步默认开启，关闭后两端都不再收发文本。

## 3. 触控目标

**决策**：触屏（`pointer: coarse` 或宽度 ≤860px）下，文件行复选框的**可点击区域**提升到 44×44，视觉方框只画 18px；圆形图标按钮在触屏提升到 44px，进度行内的小圆按钮保持 36px 以维持行高。桌面尺寸不变。

**理由**：满足 44px 触控下限，同时不牺牲桌面信息密度。

## 4. 上传响应状态码契约

**背景**：同一套 API 有两个实现（Node Hub 与 Rust Hub）。实测 `/api/upload` 与 `/api/upload/chunk` 完成时 Node 返回 `201`、Rust 返回 `200`，文档却声称两者「同一契约」。

**决策**：统一为 `201 Created`（资源创建），分块未收完保持 `200`；Rust 侧修改返回值并补测试断言，Node 侧已有断言。文档（HTTP-HUB / ARCHITECTURE）写明该契约。

**理由**：状态码是 HTTP 语义的一部分，前端目前只判断 2xx 所以功能不受影响，但对外协议必须自洽。

## 5. 支持范围（自行决定项）

| 项目 | 决定 |
|---|---|
| 操作系统 | Windows 10 21H2+ / Windows 11，仅 x64 |
| 架构 | 不提供 ARM64 / 32 位构建 |
| 浏览器 | 手机：iOS Safari 17+、Android Chrome；桌面：Edge / Chrome。Firefox 不作为验收目标 |
| 网络 | 承诺同一专用网络的单子网场景；多网卡 / VPN / AP 隔离 / 跨子网**不承诺** |
| 跨网络中继 | 标注实验性，无 WAN 生产验证承诺 |
| 签名 | 本轮不签名（见第 6 条） |

## 6. 代码签名

**决策**：1.6.0 正式版**不带签名发布**，但发布说明中显著标注「未签名，SmartScreen 可能提示」，并给出 SHA-256 供校验。

**后续可选路径**（尚未执行）：

1. **SignPath Foundation**（免费）：面向 OSI 许可的开源项目，MIT 许可符合要求；需要在 <https://about.signpath.io/foundation> 申请，通过后在 release 工作流里加签名步骤。
2. **Azure Trusted Signing**（约 $9.99/月，微软托管，SmartScreen 信誉逐步累积）：目前组织仅限美国/加拿大/欧盟/英国，个人仅限美国/加拿大，中国开发者暂不可用。
3. **商业 OV 证书 + 云签名**（SSL.com OV 约 $129/年 + eSigner 云签名套餐约 $180/年起；DigiCert KeyLocker 约 $996/年）：2023 年 6 月起私钥必须放在硬件令牌或云 HSM，不能再用普通 pfx 文件。

三种路径的 SmartScreen 表现不同：OV/标准签名需要累积下载信誉，EV 可即时获得较高信任。

## 7. 版本与发布节奏
